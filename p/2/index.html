从推理加速视角图解 DeepSeek V4.1 Flash

发布于 2026-11-04

极致压缩 Attention 开销，外挂 Engram 省下 GPU 显存。

1总览：大幅减少计算与访存

大模型推理分两段，瓶颈不同：

  • prefill 一次处理整段输入，瓶颈在算力。
  • decode 每步只生成一个 token，却要读完整的激活权重和这个请求的 KV cache，瓶颈在访存。

V4.1 Flash 把这两项开销都砍掉了一大截，prefill 和 decode 因此都快很多。

拿三个智力同档的模型来比 Decode 访存（根据 AA Intelligence Index）：

V4.1 每步读的字节最少，且上下文越长对比越明显。prefill 算力也是一样，计算量是其他两个模型的几分之一到几十分之一。

注：图 1 的权重按 safetensors 实际 dtype 统计；batch 变大时被激活的专家变多，权重读量会上升。KV 一项，V4.1 用官方 FP4 格式，含每层最近 128 个 token 的 KV；K3 按 FP8，线性注意力状态按 BF16；GLM-5.3 按 FP8 推算，78 层各存一份，另有 21 层打分用的 K，字节布局借 V3.2。图 2 一次乘加记 2，含矩阵乘、attention 和打分，口径是这么长的一段输入做冷 prefill 时的每 token 均值；V4.1 按每个输入 token 只走前 20 层计（原因见 3.1），忽略后 20 层要补算的 128 个 token。

2Attention 结构

第 1 节的两项开销，decode 读的 KV 和 prefill 的计算，主要是在注意力结构上省下来的。

2.1两种 KV，以及 DSA 稀疏注意力

V4.1 每层注意力读两种 KV（最前面两层例外，只读滑窗 KV）：

  • 滑窗 KV（滑窗注意力，SWA）：只存最近 128 个 KV，每层一份；
  • 全局 KV：覆盖全部历史，但是若干层共享一份。

传统稠密注意力每一步都要读全部历史的 KV，读的量随上下文线性增长。而 V4.1 会用一个打分器 indexer 先给每个历史位置打分，实际 Attention 只读分数最高的 512 个 KV，也就是 indexer 选中的 512 个位置（下文简称选中位置）。

indexer 打分用的索引 K 也存在全局 KV 里：全局 KV（报告里叫 global KV）= 主 KV（main KV，注意力读的 512 维向量）+ 索引 K（indexer K）。

这就是 DSA（DeepSeek Sparse Attention）稀疏注意力，在之前的 DeepSeek V3.2 就已经引入，GLM-5.3 也用了这种结构。有了 DSA，虽然 KV 的存储仍随上下文线性增长，但主注意力每一步的计算和访存都几乎退化到了常数水平。

不过 DSA 并不是没有代价的，复杂度转移到了 indexer 上，因为 indexer 需要对全量 KV 进行打分。在 V3.2、GLM-5.3 上，上下文很长时，indexer 的开销反而超过了主注意力。后面我们会提到 V4.1 Flash 对这部分同样进行了大刀阔斧的优化。

2.2encoder 和 decoder

V4.1 中，40 层分成前 20 层的 encoder 和后 20 层的 decoder，官方叫 CED（Causal Encoder-Decoder）。注意这里的 encoder、decoder 是 DeepSeek 自己针对这篇论文造的概念，和 Transformer 原论文的 encoder-decoder 不是一回事。这个模型里的 encoder 和 decoder 都是 causal 注意力。

  • encoder（L0–L19）：每隔几层就要重新算一次全局 KV（L2、L8、L14），并用 indexer 打分，临近的后面几层直接复用这份全局 KV 中被选中的位置，无需自己生成，也无需自己打分；
  • decoder（L20–L39）：
    • L20 最后一次计算全局 KV，后续层全部复用 L20 的 KV；
    • L24、28、32、36 会重新对全局 KV 打一次分，选得分最高的 512 个，给各自后续临近 3 层复用。

2.3整个模型只有 4 层全局 KV

2.1 说过，全局 KV 覆盖全部历史，上下文越长存得越多。GLM-5.3 有 78 层，就存 78 份，KV cache 随层数成倍增长，长上下文下比权重还大（见第 1 节的图）。

V4.1 的 40 层里，4 层自己算全局 KV，L0、L1 两层纯滑窗、没有全局 KV，其余 34 层直接读前面最近的那一份，份数少了一个数量级以上。

不过，滑窗 KV 依然是每层一份。一个请求的滑窗 KV 约 3 MB，和上下文长度无关；上下文短时，它和全局 KV 在同一个量级。

2.4每份全局 KV 也更小：K、V 共用，压缩，FP4

份数少了，每一份也在变小：

  • K 和 V 用同一个向量（单头 512 维），同一份既当 K 又当 V，只存一份。
  • encoder 里存全局 KV 的层每 2 个 token 压成一条，L20 不压缩：
    • 合并时用一个学出来的门控给这 2 个 token 加权（参考实现里按通道做 softmax），不是简单平均；
    • 几个 token 压成一条叫压缩比：encoder 是 2，L20 是 1。
  • 主 KV 和索引 K 都用 FP4 存。

这些都会损失一些信息。报告说训练时就用 FP4 全局 KV，"with only marginal performance degradation"（性能仅有轻微下降）。

L20 这一份给 decoder 的 20 层共用。

V4.1 约为上一代 V4 Flash 的 1/4。份数少（2.3）加上每份变小，V4.1 每 token 的全局 KV 比 GLM-5.3 占用砍掉了近两个数量级（约 60 倍）。

注：约 60 倍 = GLM-5.3 的 53,940 B ÷ 890 B，GLM-5.3 为按 FP8 推算。

2.5indexer 跨层复用打分结果，decoder 层只在候选池里打分

前面说过，indexer 每一步都要给全部历史位置打分，开销随上下文线性增长，上下文一长就超过主注意力。几代模型都在减少跑 indexer 的层数：

GLM-5.3 已经让相邻 4 层共享一次 indexer 的结果（78 层里 21 层跑 indexer），V4.1 则更进一步，把全局 KV 和选中位置的跨层复用、分块候选池合在一起，报告里叫 CSA2（Compressed Sparse Attention 2），把层分为三类：

  • Full：自己算全局 KV，自己跑 indexer。
  • Reindex：全局 KV 读前面层的，用自己的索引 Q 重新选一次位置。
  • Reuse：全局 KV 和选中位置都复用前面层的。

decoder 里每 4 层（L24、L28、L32、L36）重新选一次位置，选出的位置在临近的后几层直接复用。而且 decoder 里 Reindex 层的打分范围，由 L20 给出，后续层只在几块固定的区域打分：

  1. L20 给全部历史打分，把位置每 8 个分成一块，块的分数取块内最高分。
  2. 选出分数最高的 2048 块，组成候选池。
  3. L24、L28、L32、L36 只给池里的位置打分，各自选出要读的位置。

这有点像搜索里的召回加精排：先按块粗挑一小批，再在这一小批里细挑。

L24、L28、L32、L36 每一步打分的位置数因此固定为 16,384 个，不再随上下文增长。不过：

  • 上下文不到 16K 时，候选池就是全部历史，什么也没省。
  • 给全部历史打分的那几层仍随上下文线性增长。

2.6总览：一层注意力里的四路数据

对照着下图，把 2.1 讲的两种 KV 和 indexer 放进具体的一层里看。点击图片切换层号可以看到每种层的样子（仅在 unitstride.com 网站内浏览可以点击），默认展示 Full 层（L2）：

  • Q 支路：算这一层自己的查询向量，64 个头共用同一份 KV。
  • 滑窗 KV 支路：算本层最近 128 个 token 的 KV。
  • 主 KV 支路：压缩出全局 KV 里的主 KV。最近的位置同时有滑窗 KV 和主 KV 两份；压缩比 2 的层里，还没凑满一组的最新位置先暂存，暂时还没有主 KV。
  • indexer 支路：用索引 Q 和索引 K 打分，得到选中位置。

最终，滑窗 KV 支路产出最近的 128 个 Token 的 KV，主 KV 支路 + indexer 支路选出得分最高的 512 个 KV，这两部分 KV concat 到一起。Q 和这 512 + 128 = 640 个 KV，一起被送进 sparse_attn 中计算注意力得分。

注：上下文不足 512 个位置时，选中的是 min(512, T) 个，T 是主 KV 的可见条数。

3SWA Bounded Replay：用近似的滑窗 KV 换计算和存储

V4.1 每一层都有滑窗注意力，prefill 结束时要把每层最后 128 个 token 的滑窗 KV 交给 decode。

3.1decoder 层为什么不用算全部 token

2.2 说过，decoder 用的全局 KV 就是 L20 那一份，算好后给全部 decoder 层用，L21–L39 不自己算全局 KV。

prefill 结束时要交给 decode 的，是最后一个 token 的 logits、全局 KV，以及每层最近 128 个 token 的滑窗 KV。全局 KV 在 L20 算完就齐了，decoder 层还缺的，是最后 128 个 token 的滑窗 KV。

所以 prefill 时，decoder 层只需要让最后 128 个 token 的 query 去读全局 KV 和滑窗 KV，前面的 token 都不用进 decoder。

不过不能每一层都只算最后 128 token，否则会丢失信息。例如下面的例子：最后一层这 128 个 token 的滑窗 KV，由这一层在这 128 个位置的输入算出，也就是上一层同样位置的输出；上一层要算这 128 个输出，每个位置都要读前面 128 个位置的滑窗 KV，所以要准备 128 + 128 个位置，再往上一层再多 128 个。

精确重算时，decoder 要算一个倒梯形：最后一层 128 个，往上每层多 128 个，到 L20 约 2560 个（128 × 20）。

3.2decoder 部分的 Bounded Replay：prefill 只让最后 128 个 token 过 decoder

报告里有两处同名的 Bounded Replay，在同一个模型里同时使用：decoder 部分的（官方名 Decoder SWA Bounded Replay）省 prefill 计算，encoder 部分的（官方名 Encoder SWA Bounded Replay）省 KV cache 的存储；两处都是用近似的回放（replay）代替精确重算。

V4.1 测评发现，CED 精确方案还可以更进一步：无需倒梯形重建，每层就只算最后 128 个 token（这就是 Bounded Replay）。测评结果显示对回答质量的影响可以忽略，并且在后训练时模拟了同样的回放，让模型适应。

可以看到，prefill 时，相比起其他模型所有层全部算满的方案，CED + Bounded Replay 让 decoder 层的计算几乎可以被忽略，整体计算量剩下约一半。不过前提是输入较长；如果输入不超过 128 个 token，这些 token 本来就都要过 decoder，decoder 层的算力就没省。

注：报告原句 "CED successfully reduces nearly half of the prefill computation while maintaining performance comparable to the baseline."（§2.2）

3.3encoder 部分的 Bounded Replay：滑窗 KV 只保留几分钟

全局 KV 和滑窗 KV 分在两个池子里存放，可能出现全局 KV 命中、滑窗 KV 没命中的情况。

如 3.1 所讲，滑窗 KV 没命中时，要从 L19 往上按倒梯形重建：最后一层算 128 个，倒数第二层 256 个，以此类推。这里同样可以用 Bounded Replay，评测同样显示对质量几乎没有影响：encoder 每层的滑窗 KV 都只重建最后 128 个。

这带来的变化是：

  • 原来：要重建的 KV 很多，没命中时重算代价很大，只能尽量把滑窗 KV 留着、别让它没命中，占用更多 KV 存储空间；
  • 现在：改成 Bounded Replay 之后，每次重算的代价变得很小，滑窗 KV 没那么重要了；
  • 结果：可以把它的保留时间（TTL）大幅缩到分钟级，腾出更多 cache 空间。

4Engram：按 n-gram 查表，表放在主机内存

以前的模型里，记住的知识和做计算的能力放在同一批权重里（attention 和 MoE 的权重）。这些权重都要常驻 GPU 显存，其中被选中的专家每步参与计算。

报告对 Engram 的定位是 "the conditional memory module introduced in our previous work to decouple memorization from computation"（我们之前提出的条件记忆模块，用来把记忆和计算分开）。它把一部分能由最近几个 token 的组合直接查到的内容，放进按 n-gram 查表的大表里：查表只按地址取一行，不做矩阵乘。

V4.1 的 Engram 有 196B 参数，分成两个模块，在 L1 和 L14 把查表结果写入残差流。每个位置取以它结尾的最近 2、3、4 个 token。token 先归并成压缩后的 id（例如 " The"、"the"、"THE" 会归成同一个）。每种长度用 8 个哈希各算出一个地址，一共 24 个地址，各从表里取出一行向量。

这 24 行拼起来做一次投影，得到要加进去的值，以及和当前隐藏状态比对用的键。键和隐藏状态越吻合，门控越接近 1，值加进去得越多；不吻合就基本不加。

查哪几行只取决于 token，不依赖前面层算出来的结果，所以地址可以在计算开始前就算好。

官方推理把表放在主机内存，省下大量 HBM 开销。后台通过 RDMA 提前把要用的行取过来，L1 那个模块的预取和 L0 的计算同时进行。

这样，原本只能靠计算去「模拟」查找的一部分知识，变成了在主机内存里按地址查表：省下 HBM 显存；取回的向量还要在 GPU 上做投影和门控，但比稠密的矩阵运算便宜得多。

两张表的 FP8 载荷约 197 GB，含 scale 约 203 GB。

注：「靠计算去模拟查找」出自 Engram 论文（arXiv:2601.07372）摘要："Transformers lack a native primitive for knowledge lookup, forcing them to inefficiently simulate retrieval through computation"。V4.1 的 Engram 是在 MoE 之外另加的模块。

5mHC：残差从一条流变成四条

之前模型残差大多是一条流：每个子层（attention 和 MoE 各算一个子层）从流上取一份输入去算，结果加回流上。

mHC（Manifold-Constrained Hyper-Connections）把残差改成 4 条流：embedding 之后复制成 4 条完全一样的流。V4.1 的 80 个子层，每个都做三步：

  1. 输入合成 A：4 条流各乘一个数再相加，合成一条送进子层。
  2. 写回 C：子层的输出乘一个数，加到每条流上。
  3. 流间混合 B：每条新流从 4 条旧流（包括自己）各取一部分。

4 条流都要读写，激活值访存变多了。把一条流里一个 token 的 5120 个值记作 1d，报告给了每个 token、每个子层读和写的总量（读、写都算）：

  • V4 原实现 20d：残差更新、系数预测、输入合成是依次执行的三个 kernel，每个都要读一遍。
  • Mega-mHC 融合、结构不变 14d：三步融成一个 kernel，残差更新和系数预测共用一遍读取，这是纯算子优化。输入合成仍要等这次的 A，而 A 要等一整行都读完才算得出来，所以得再读一遍。
  • Mega-mHC 加 Single-Pass 10d：输入合成改用上一次预测好的 A，不用再等，一遍读完。这改的是模型结构，V4.1 的权重就是按它训练的。

mHC 不影响 KV。激活值访存比起权重和 KV 很小，所以 Single-Pass 和 Mega-mHC 省下的这部分只是小优化，不是 V4.1 快的主因。以 batch = 1 的 decode 为例，每个 token 约 8 MB（80 个子层 × 10d × 每个值 2 字节），而权重每步要读 13 GB。

6DSpark

V4.1 还自带推测解码模块 DSpark。推测解码是先用一个小的草稿模块猜出后面几个 token，再让主模型一次前向验证，猜对几个就一次出几个。DSpark 的草稿器一次给出多个候选 token，再按置信度决定每个请求实际验证几个。

DSpark 在本代模型中没有什么特别的优化，因此不特别介绍，可以参考其他文章，或者后续有机会再单独出一篇。

7总结

过去全局 KV 太长，占用显存多，Attention 计算也慢。业界用 indexer 把注意力稀疏化，每次只让最相关的若干个 KV 参与 attention，但 indexer 又成了新的瓶颈。

V4.1 更进一步：跨层复用并压缩全局 KV，复用 indexer 的结果，再用候选池先粗选、再细选，同时大幅压缩了全局 KV 的存储和 indexer 的开销。CED 加上 Bounded Replay，让 prefill 的计算量减少约一半。Engram 把一部分知识从计算里拿出来，改成在主机内存里按地址查表，减少了 HBM 占用，也比稠密的矩阵运算便宜。

在效果优于 V4 Flash 的前提下，这些改动大幅降低了推理成本。
